# Avianca TMS demo — instructions for Claude

This folder (`C:\Avianca TMS`) is the demo built for Avianca ("Ava demo"). Every Claude session
working here — Cowork, Claude Code, mobile — follows these rules. They are binding, not advisory.

## Read order

1. `docs/00_SCOPE.md` — what is in, what is out, the date.
2. `docs/03_DEMO_SCRIPT.md` — the walkthrough decides what gets built. Nothing off-script is built.
3. `scaffold/CLAUDE.md` and `scaffold/README.md` — the kit's own rules; they apply unchanged.
4. Only then the kit doc the current slice needs (`kit-docs/NN_*.md`), never the whole folder.
5. Project state lives in the brain: `corvanox-brain/avianca-tms/STATUS.md` + `TODO.md`.

## Standing rules

1. **Source of truth is the TMS Kit.** The scaffold in `scaffold/` was copied from the kit; the
   blueprint in `kit-docs/` wins wherever the scaffold disagrees. The framework is the shipped
   ICAO/EASA catalogue — 9 competencies, 73 observable behaviours — used as data, never edited.
2. **No material from any other engagement or operator.** No names, records, vocabulary, screenshots,
   templates, hostnames or code from any other client system enters this folder — not as reference,
   not as a comment, not as a placeholder. `npm run verify` runs a neutrality scan against a word list
   that lives OUTSIDE this repository (`NEUTRALITY_WORDLIST` in `.env`); a hit fails the gate.
3. **Scope is fixed:** ETR, Program Builder, QMS, DMS, analytics with gated AI narrative, PDF export,
   Avianca brand, EN first with ES toggle. **No dispatch / crew-scheduling module.** No LMS or roster
   integration. Do not build what `docs/03_DEMO_SCRIPT.md` does not show.
4. **Isolation is by name and port, and both are fixed** (`docs/01_ISOLATION.md`): compose project
   `ava`, containers `ava-*`, app on 3100, database on 5433, PDF renderer on 3101, cookie
   `ava_session`. Never touch another compose project, container, volume or port on this machine or
   on the server.
5. **The database is never copied anywhere.** Every environment is `migrate → seed` from this repo.
   Seed data is synthetic and generated by script (`docs/04_SEED_DATASET.md`). No real person, no
   real record, ever.
6. **Deploy path is git + compose only** (`docs/02_DEPLOY_PATH.md`). No file-copy scripts to the
   server, no database dumps to the server, no `.env` copied between hosts.
7. **Secrets never enter this folder.** `.env` is git-ignored and referenced by vault entry
   (`vault: Avianca/…`). If a secret is pasted in chat, it is not persisted.
8. **One vertical slice at a time**, finished: schema → library → route → screen → smoke check →
   doc line. Never two modules at once. Git tag before each slice.
9. **Brand lives in `scaffold/config/brand.yaml` only** (`docs/05_BRAND.md`). No colour literal,
   font name or product name in a component.
10. **Every screen built here is written against the kit's spec** so it can be folded back into the
    kit afterwards. When a kit doc is silent or wrong, log it in `docs/KIT_DEFECTS.md` — that log is
    the replication trial's output.

## Closing routine

Before ending any session that changed state: update the brain (`avianca-tms/STATUS.md`, `TODO.md`,
`PLAN.md` if a milestone moved, `DECISIONS.md` for any decision), append to `docs/KIT_DEFECTS.md`
if the kit was found wanting, then `git add -A; git commit -m "session: ava — <summary>"`.
